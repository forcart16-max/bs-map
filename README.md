# BSMAP v3

Інструмент для нанесення азимутальних секторів базових станцій на
безкоштовні карти (без API-ключів). Тепер розгортається як сайт на
**Cloudflare Pages**, доступ до якого захищено логіном і паролем
(HTTP Basic Auth через Cloudflare Pages Functions), і має експорт
карти в PNG та PDF.

## Структура проєкту

```
bsmap/
├─ public/
│  └─ index.html       ← сам застосунок (карта, сектори, UI)
├─ functions/
│  └─ _middleware.js    ← Basic Auth-гейт: перевіряє логін/пароль на КОЖЕН запит
├─ wrangler.toml
├─ package.json
└─ README.md
```

`functions/_middleware.js` виконується на Cloudflare Workers runtime
(Pages Functions) і перехоплює будь-який запит до сайту (`/*`) до того,
як віддадуться файли з `public/`. Без правильних логіна й пароля сайт
взагалі не відкриється — навіть index.html не завантажиться.

## Розгортання на Cloudflare

### Варіант A — через дашборд (найпростіше)

1. Створіть git-репозиторій (GitHub/GitLab) і запуште туди цю теку.
2. У Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages**
   → **Connect to Git**, оберіть репозиторій.
3. Build settings:
   - Framework preset: `None`
   - Build command: (залиште порожнім)
   - Build output directory: `public`
4. Після створення проєкту зайдіть у **Settings → Environment variables**
   і додайте (як **Secret**, не як звичайну змінну):
   - `AUTH_USER` — логін
   - `AUTH_PASS` — пароль
   Додайте їх окремо для Production і Preview, якщо плануєте
   використовувати preview-деплої.
5. Redeploy (Settings → Deployments → Retry deployment), щоб змінні
   підхопились.
6. Відкрийте виданий `*.pages.dev` домен (або підключений власний
   домен) — браузер запитає логін/пароль.

### Варіант B — через Wrangler CLI

```bash
npm install
npx wrangler login

# один раз — прив'язати секрети до проєкту
npx wrangler pages secret put AUTH_USER
npx wrangler pages secret put AUTH_PASS

# деплой
npm run deploy
```

Локальна перевірка перед деплоєм (з тими ж секретами):

```bash
npx wrangler pages dev public --binding AUTH_USER=admin --binding AUTH_PASS=secret
```

## Авторизація — як це працює

- Використовується стандартний **HTTP Basic Auth**: браузер сам показує
  системне вікно логіна, окремої сторінки входу не потрібно.
- `functions/_middleware.js` звіряє введені дані з `AUTH_USER`/`AUTH_PASS`
  константним за часом порівнянням (щоб не можна було підібрати пароль
  по швидкості відповіді).
- Якщо секрети не задані — сайт навмисно повертає 500 і **не** віддає
  застосунок (fail-closed), щоб випадково не залишити його відкритим.
- Це проста та надійна схема "один спільний логін/пароль на сайт".
  Якщо потрібні **декілька окремих користувачів**, власна сторінка
  входу замість системного вікна, або збереження проєктів у спільному
  сховищі (а не лише в localStorage браузера) — це вже наступний крок
  (сесії через cookie + Cloudflare KV/D1); скажіть, і я допишу.

## Експорт карти

У нижній панелі з'явились дві нові кнопки:

- **🖼 PNG карти** — рендерить видиму область карти (тайли + всі
  азимутальні сектори) в один PNG-файл і одразу завантажує його.
- **📄 PDF карти** — те саме зображення, вставлене в PDF-сторінку
  розміром під сам знімок карти.

Технічно це `html2canvas` (знімок DOM-карти у canvas) + `jsPDF`
(обгортання зображення в PDF); обидві бібліотеки підвантажуються з
cdnjs, тож для експорту потрібен інтернет, як і для самих тайлів карт.
Базові шари (Esri, Wikimedia OSM) віддають тайли з CORS-заголовками,
тому знімок не "тайниться" — але якщо колись зміните джерело тайлів
на таке, що не дає CORS, експорт зображення почне падати з помилкою
(сама карта в браузері працюватиме як і раніше).

## Примітки

- Дані (сектори, адреси, збережені проєкти) все ще зберігаються в
  **localStorage браузера** — окремо для кожного пристрою/браузера.
  Логін/пароль контролює лише доступ до сайту, а не спільне сховище
  даних між користувачами чи пристроями.
- Пошук адрес (Nominatim) виконується прямо з браузера користувача —
  йому також потрібен інтернет-доступ (це не змінилось).
